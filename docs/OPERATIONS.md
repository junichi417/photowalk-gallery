# 運用手順：受付期間・締切後・削除依頼

## 写真の置き場所（3か所）
| | 受付期間（〜10/31） | 締切後（11/1〜） |
| --- | --- | --- |
| 公開サイト | GitHub Pages（gh-pages）＝画面だけ。写真は Supabase から表示 | GitHub Pages（gh-pages）＝**画面＋写真のすべて** |
| 元データ | Supabase（DB＋ストレージ） | Supabase（そのまま残す。放置すると一時停止するが、期限内なら再開できる。だから本命は静的版と控え） |
| 控え | — | 社長の手元（静的版をzipで保存。Googleドライブなど） |

- `main` ブランチには**本番の写真を一切入れない**（コードと仮画像だけ）。
- `gh-pages` は毎回「履歴なしの1コミット」で上書きする。削除した写真が履歴に残らない。

## 受付期間中（エマが毎日）
- 管理画面で新しい写真を確認。問題があれば**非公開**にして社長に報告（削除は社長の判断）
- Supabase の Usage で**通信量（月5GB）・保存容量（1GB）**を確認。7割を超えたら社長に報告
- 合言葉が外に漏れた疑いがあれば、社長が管理画面で**変更**（登録済みの人はそのまま投稿できる）

## 締切（10/31 23:59 JST）
- 何もしなくても、23:59:59 を過ぎるとサーバーが投稿を拒否する（テスト済み）
- 画面は自動で「写真の受付は終了しました」に変わる

## 締切後の切り替え（11/1、社長の承認後）
1. 公開版を書き出す（写真をすべてダウンロード）
   `python3 tools/build_site.py archive --url <Project URL> --anon-key <公開用キー>`
2. 枚数と `events/<イベント>/manifest.json` を確認。手元で `python3 -m http.server -d dist` で表示確認
3. 公開：`tools/publish_pages.sh dist`
4. `dist` を zip にして社長に渡す（控え）
5. 管理画面で受付スイッチをオフ、合言葉を無効化（念のため）

これで Supabase が止まっても、ギャラリーは GitHub Pages だけで表示され続ける。費用は0円のまま。

## 削除依頼が来たら
**受付期間中**：管理画面で該当の写真を「削除」（ファイルも消える）。名前だけ消したい場合は「名前を隠す」。

**締切後**：
1. 依頼の写真を特定し、写真ID（ファイル名の `<ID>.jpg`）を確認
2. `python3 tools/remove_photo.py <写真ID>`
3. `tools/publish_pages.sh dist` で公開し直す（履歴にも残らない）
4. Supabase の管理画面からも削除（Supabase がまだ動いていれば admin.html の「削除」）
5. 社長の手元の控え（zip）からも同じファイルを消す
6. 対応したことを日誌に記録（依頼者の個人情報は書かない）

※ 検索エンジンや閲覧者の端末に一時的に残った画像は、こちらでは消せない。必要なら Google の「古いコンテンツの削除」ツールで申請する。

## 次回のフォトウォーク（小豆島など）
- `events/<新しいイベント名>/event.json` を作る
- SQL Editor で `insert into public.events (slug, title, submission_deadline) values (...)`
- 同じ Supabase・同じ仕組みで動く（無料枠は全イベントの合計）
